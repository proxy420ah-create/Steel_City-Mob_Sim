  • GangDispatcher — iterates all hoods, starts working phase, manages gang roster

💡 Key RE Insight: Per-Hood Independence

Each hood has its own order queue, time budget, and state machine. The gang dispatcher iterates all hoods but each runs independently. This maps cleanly to N SimulationManager instances — one per hood.

HoodAgent — Movement

Real-time A* pathfinding via shared Pathfinder. Waypoint lerp movement. Face direction rotation. Ground Y from VoxelCollisionWorld probe. From StressTestAgent — proven at 100 agents.

HoodAgent — Game Logic

Order queue (List<Order>). Time budget (12,000 ticks/week). State machine: Idle → PathToTarget → ExecuteOrder → PathHome → Idle. Order resolution (extort, collect, kill). Tick consumption per action. From SimulationManager.

HoodAgent — Animation

Drives CharacterAnimation states: Walking (moving), Checking/Aiming (at target), Idle (waiting), Falling (airborne). Voxel group transforms for articulated limbs.

HoodAgent — Rendering

Via VoxelCharacter: GPU instanced (Tier 2). animState, animTime, animSpeed in instance buffer. 1 draw call for all hoods regardless of count.

💡 Decoupled Movement and Game Logic

Movement uses real-time Time.deltaTime lerp (proven by StressTestAgent). Game logic uses tick-based countdown (order action times from RE data). These are decoupled: movement is visual, ticks are logical. A hood can be visually walking while its tick budget counts down.

⏱️ Tick Budget — 12,000 Ticks Per Hood Per Week

Every hood gets the same budget. Orders consume ticks. Walking consumes ticks. When budget = 0, hood goes home.

💡 Budget Exhaustion = Go Home

When a hood's tick budget hits 0, the current order is abandoned and the hood paths home. This means a hood with a Kill order (6,000 ticks) plus walking time may not complete a second order that week. The player must budget wisely — just like the original game.

Distance Threshold: 64 Units

From RE: if target is > 64 game units away, hood is assigned a vehicle. This is roughly 2-3 city blocks in our scale. Shorter distances = walk. This prevents hoods from driving across the street.

Simple, deterministic
🎲

Random 25% for Special Orders

For high-priority orders (kill, bomb), there's a 25% chance of random vehicle assignment regardless of distance. Adds unpredictability — sometimes a hood drives to a nearby hit, sometimes walks.

RNG-based, adds variety
🔑

Vehicle Pool

Vehicles are shared gang resources. GangDispatcher manages a pool of available vehicles. When a hood needs a car, one is assigned from the pool. When the hood returns home, the vehicle returns to the pool.

Shared resource
🚶

Walking Fallback

If no vehicles are available in the pool, the hood walks regardless of distance. This can cause long travel times and tick budget exhaustion — strategic vehicle management matters.

Strategic constraint
💡 Two Vehicle Flag Systems in Original

The RE data reveals two separate vehicle flag systems — one for the distance-based path and one for the random path. These are independent and can overlap. Our implementation will unify them into a single VehicleAssignment component per hood.

Current: 16 bytes (pos + yaw). Phase 1: +animState, animTime = 24 bytes. Phase 2: +animSpeed = 28 bytes. Phase 3 (groups): +faction, health = 32 bytes. All backward-compatible — unused fields zeroed. See DYNAMIC_OBJECT_RENDERING_TIERS.md for tier classification.

🔧 Physics & Spawn Fix

Ground probing replaces hardcoded Y. No more floating or underground hoods.

❌ Current — Hardcoded Spawn Y

  • Spawn at fixed Y=0 (or hardcoded offset)
  • Falls through terrain on uneven ground
  • Log spam from ground snap attempts
  • Single Vinny = manually positioned
  • Stress test = random Y, often wrong

✅ Proposed — Ground Probe Spawn

  • Spawn at Y+50, probe downward via VoxelCollisionWorld
  • Snap to ground surface height
  • Increased snap distance (50 units)
  • Log spam reduced — only log on failure
  • Works for any terrain height across 100 blocks

💡 Why Y+50?

The tallest buildings in Steel City are ~40 units. Spawning at Y+50 guarantees the probe starts above any terrain feature. The downward raycast via VoxelCollisionWorld finds the actual ground surface. This replaces the old hardcoded Y that assumed flat terrain.

With 100+ hoods, a follow cam only shows one. The overhead camera lets the player see the whole gang's movement — which is the point of the simulation. Street free-cam is a future flavor feature for screenshots, not a gameplay requirement.

🎯 Physical Projectiles & Crossfire

No physics engine. Just a spatial hash + distance checks. Stray bullets create stories.

Hitscan (Baseline)

  • Instant raycast — target hit or missed
  • No travel time — can't dodge, can't lead
  • Only the intended target can be hit
  • No stray bullets — no crossfire casualties
  • Simple, deterministic

Physical Projectiles (Recommended)

  • Lightweight entity: position, velocity, TTL
  • Travel time — suppression, dodging, leading targets
  • Stray bullets hit anyone — civilians, cops, rival hoods
  • Crossfire creates mayhem → peds scatter, police escalate
  • Drive-by sprays actually spray a street
  • Witnesses generated → investigations → consequences

💡 Why Not Unity Physics?

Unity Rigidbody + Collider = broadphase + solver + contact pairs. Scales to ~50 entities before lag. Our spatial hash = O(N) dictionary bucketing + O(P×k) distance checks. Scales to 500+ instances and 200+ projectiles. We need "does this point overlap this sphere" — not resting contacts, stacking, or joints. The spatial hash is the right tool.

💡 The Mob Sim Value

In a mob sim, the stories come from things going wrong. A hit goes sideways because a pedestrian walked into the crossfire. A drive-by catches a rival who happened to be walking past. Physical projectiles create these moments — and the spatial hash makes it cheap enough for 500+ instances.

💡 Key Architectural Decision: Shared Pathfinder

All HoodAgents share a single Pathfinder instance and WaypointGraph. Pathfinding is done on-demand (when a hood needs a new path), not every frame. The waypoint graph is static — built once at city generation. This means 100 hoods can pathfind without 100 separate graph copies.
