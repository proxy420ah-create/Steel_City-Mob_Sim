Executive Summary

What We Have

A complete voxel character animation pipeline with two rendering paths:

  • C# Forward-Transform Test Rig — CPU poses voxels each frame, uploads to GPU for pure raymarch display. VERIFIED
  • GPU Shader Inverse-Transform — Shader applies per-group rotations during raymarch using inverse sampling. IN PROGRESS

Both paths share the same animation math (Catmull-Rom keyframes, FK chains, pivots) — one in C#, one in HLSL.

What's Broken

The production character character_hoodlum_0 has a .groups file where all 2304 voxels are assigned groupID = 0 (Body). No voxels are tagged as head, arms, legs, etc. — so the shader has nothing to articulate. The animation system is working; the model's group data is missing.

What We Need To Do

Re-paint group IDs on the character_hoodlum_0 model in the Voxel Editor, then re-export. The animation code (C# animator, shader keyframe interp, pivot buffer) is already implemented and working — it just needs a model with correct group assignments.

Asset Pipeline: Authoring → Export → Unity

Two Rendering Paths

Path A: C# Forward-Transform Test Rig

WORKING

StepWhat happens
1. LoadRead .stasset, .groups, .anim.json from disk
2. PoseVoxelCharacterAnimator.PoseVoxels() transforms each voxel to posed position using FK chains + Catmull-Rom interpolation
3. ScatterRound posed positions to nearest grid cell in a padded grid
4. UploadWrite padded grid to ComputeBuffer, register with VoxelChunkManager
5. RenderShader does pure raymarching — no group IDs, no animation logic. Just renders the posed voxel cloud.

Controls: W=Walk, T=TPose, I=Idle, A=Aim, C=Crouch, Space=Play/Pause

File: ForwardTransformTestRig.cs

Purpose: Verify the C# animation math is correct before porting to HLSL.

Path B: GPU Shader Inverse-Transform

IN PROGRESS

StepWhat happens
1. LoadVoxelCharacter loads .stasset + .groups, registers as instanced character
2. ParamsVoxelCharacter.LoadAndApplyAnimParams() loads .anim.json, pushes keyframes + pivots to shader buffers
3. DriveCharacterAnimation pushes animState/animTime/animSpeed per instance
4. RenderShader raymarches through posed space. At each step, inverse-transforms the sample position back to rest space to read the voxel grid.
5. AnimateComputeGroupRotation() in HLSL computes per-group rotation matrices from keyframe buffers + pivot buffer

Controls: 1=Idle, 2=Walking, 3=Looking, 4=Checking, 5=Aiming, 6=Crouching

File: VoxelProxyRaymarch.shader, VoxelCharacter.cs, CharacterAnimation.cs

Purpose: Production — render hundreds of instanced characters with GPU-side animation.

Key Insight: Same Math, Different Direction

Both paths use the same animation math (Catmull-Rom keyframes, FK parent-child chains, pivot-based rotation). The difference is direction:

  • Path A (Test Rig): Forward — transform rest voxels → posed voxels → render posed cloud
  • Path B (Shader): Inverse — ray steps through posed space → inverse-transform back to rest → sample rest grid

Path A is for verification. Path B is for production (instancing, performance).

Data Files

ExtensionFormatContentsConsumed ByStatus
.stasset Binary (STAS header + ushort grid) Voxel material IDs in a W×H×D grid. 0 = air, 100+ = material index. Both paths (Test Rig + Production) OK
.groups Binary (STAG header + ushort grid) Per-voxel group ID (0-9). Same dimensions as .stasset. Critical for animation. Both paths BROKEN for character_hoodlum_0
.anim.json JSON (text) Pivots (10 entries), walkKeyframes (4 KFs), jointConfig (axis/sign/rest), aiming/crouching params Both paths (Test Rig via LoadFromAnimJson, Production via LoadAndApplyAnimParams) OK

The .groups File Is The Blocker

The character_hoodlum_0.groups file contains all zeros — every voxel is groupID 0 (Body). This means:

  • The shader sees only "body" voxels — no limbs to rotate
  • The test rig sees only "body" voxels — no limbs to pose
  • Animation states (Walking, Aiming, etc.) have no visible effect because there are no arm/leg/head groups to transform

The fix is NOT in the code — it's in the model data. The model needs to be re-painted with group IDs in the Voxel Editor, then re-exported.

Forward Kinematics (FK) Hierarchy

Both the C# animator and the HLSL shader use this same 10-group hierarchy. Each group is a body part that rotates around its pivot point. Child groups inherit their parent's transform chain.

Group 0: Body (root) — torso twist, crouch lean ├── Group 1: Head — yaw + pitch + tilt ├── Group 2: Left Arm — shoulder swing │ └── Group 8: Left Forearm — elbow hinge ├── Group 3: Right Arm — shoulder swing │ └── Group 9: Right Forearm — elbow hinge ├── Group 4: Left Leg — hip stride │ └── Group 6: Left Shin — knee hinge └── Group 5: Right Leg — hip stride └── Group 7: Right Shin — knee hinge

What Does NOT Need To Change

The following are already implemented and working — they just need a model with correct group data:

  • Shader keyframe interpolation — Catmull-Rom, mirror, body bob, weight shift DONE
  • Shader pivot buffer — _Pivots StructuredBuffer with authored per-model pivots DONE
  • C# animator — VoxelCharacterAnimator.cs with full FK chain, all states DONE
  • Animation parameter loading — VoxelCharacter.LoadAndApplyAnimParams() pushes keyframes + pivots to GPU DONE
  • HoodSpawner — Auto-spawns debug hood, provides 1-9 hotkeys DONE
  • CharacterAnimation — Drives animState/animTime/animSpeed per instance DONE

Do Not Confuse The Two!

W controls the Test Rig (C# forward-transform, CPU-posed).

2 controls the HoodSpawner's character (GPU shader, inverse-transform).

They are separate characters with separate animation drivers. The Test Rig is for verifying math; the HoodSpawner character is for testing the production shader path.

How HoodSpawner Gets Added To The Scene

CityMap3D.cs automatically adds a HoodSpawner during city generation if one doesn't already exist:

// CityMap3D.cs — during SpawnSceneCharacters()
if (FindFirstObjectByType<HoodSpawner>() == null)
{
    var hoodObj = new GameObject("HoodSpawner");
    hoodObj.transform.SetParent(mapRoot, false);
    var hs = hoodObj.AddComponent<HoodSpawner>();
    Debug.Log("[CityMap3D] Added HoodSpawner to scene");
}

The HoodSpawner then:

  1. Waits 2 frames (for city build to complete)
  2. Finds an empty plot block in the city layout
  3. Ground-probes to find the surface Y
  4. Creates a GameObject with VoxelCharacter + CharacterAnimation + PedestrianLookAround
  5. Sets characterAsset = "character_hoodlum_0.stasset"
  6. Focuses camera on the spawned character

The VoxelCharacter component loads .stasset + .groups + .anim.json from StreamingAssets/voxel_characters/ and registers with VoxelChunkManager for instanced raymarch rendering.
