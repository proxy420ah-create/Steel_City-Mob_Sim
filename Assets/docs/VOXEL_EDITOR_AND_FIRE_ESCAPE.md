## 1. Voxel Editor HTML System

### Overview

The voxel editor is a **browser-based 3D voxel editor** generated by `voxel_editor_html.py`. It produces a self-contained HTML file with Three.js + InstancedMesh + raycasting that runs in any modern browser — no server required.

### Entry Point

```python
import voxel_editor_html as veh
veh.voxel_to_editor(grid, (W, H, D), "voxel_editor.html", title="My Model")
```

- `grid`: numpy array `(W, H, D)` of `uint16` material IDs
- `dims`: tuple `(W, H, D)`
- `filepath`: output HTML path
- `title`: browser tab title

### Architecture

The generated HTML file contains:
- **Three.js r160** (loaded from CDN) with `InstancedMesh` for performant voxel rendering
- **OrbitControls** for camera movement (LMB rotate, RMB pan, wheel zoom)
- **Raycasting** against voxel instances for click-based tool actions
- **Material palette** sidebar with color swatches and selection
- **Tool bar** with mode switching and keyboard shortcuts
- **Y-slice controls** for layer-based visibility filtering
- **Status bar** showing coordinates, voxel counts, and tool feedback

### Tools & Keyboard Shortcuts

| Tool | Key | Description |
|------|-----|-------------|
| Camera | `C` or `Esc` | Orbit/pan/zoom only — no editing |
| Paint | `P` | Click voxel to paint with selected material |
| Erase | `E` | Click voxel to remove |
| Box | `B` | Click-drag to fill rectangular volume |
| Line | `L` | Click two points for a line |
| Select | `S` | Flood-fill select same material |
| Extrude | `X` | Click face + drag to extrude |
| Ruler | `R` | Click two points to measure distance |

### Selection Modes (Enhanced)

| Mode | Input | Behavior |
|------|-------|----------|
| Flood-fill | Click | Select all connected voxels of same material |
| Single voxel | `Shift+Click` | Select one voxel only (good for railings) |
| Box select | `Ctrl+Click` two points | Select all non-air voxels in 3D bounding box |

### Escape Key (Universal Reset)

Pressing `Escape` clears ALL tool states and switches to camera mode:
- Clears: `lineStart`, `boxStart`, `rulerStart`, `extrudeDragActive`, selection
- Calls `clearHighlight()` and `setTool('camera')`
- No highlights or tooltips shown in camera mode

### Volume Expansion

The editor supports dynamic grid resizing via the **Expand Volume** modal:
- Accessible via the Expand button in the toolbar
- Add space on any axis (X/Y/Z) in either direction (−side shifts voxels, +side adds empty space)
- Existing voxels are shifted when expanding in the − direction
- Grid floor and camera target update automatically

### 3-Axis Slice Controls

The right panel has min/max sliders for all 3 axes:

| Axis | Sliders | Use Case |
|------|---------|----------|
| **Y** | `yMin` / `yMax` | Floor levels, editing interiors |
| **X** | `xMin` / `xMax` | Left/right cross-sections |
| **Z** | `zMin` / `zMax` | Front/back cross-sections (e.g. isolate fire escape at Z=87-95) |

- Voxels outside any slice range are hidden (not deleted)
- Sliders auto-clamp (min cannot exceed max and vice versa)
- Layer info text shows active filters, e.g. `Y=10-18 | Z=87-95`
- All axes at full range shows `All layers visible`

### Save/Load

- **Save**: Exports voxel data as JSON (dims, materials, voxels array)
- **Load**: Imports JSON voxel data back into the editor
- **Export .stasset**: Binary format for Unity consumption

### Key Variables in Generated JavaScript

| Variable | Purpose |
|----------|---------|
| `W, H, D` | Grid dimensions (mutable `let` for expansion) |
| `voxelMap` | `Map` keyed by `"x,y,z"` storing material IDs |
| `gridHelper` | Three.js `GridHelper` instance (mutable for resize) |
| `controls` | OrbitControls instance |
| `yMin, yMax` | Visible Y-slice range |
| `xMin, xMax` | Visible X-slice range |
| `zMin, zMax` | Visible Z-slice range |
| `currentTool` | Active tool string |
| `clipboard` | Array of copied voxels for paste operations |
| `pasteOffset` | `{x, y, z}` offset for paste positioning |
| `selVoxels` | Array of selected voxel coordinates |

### ⚠️ Editing Gotcha: grep Cannot Find f-string Template Content

**Problem**: `grep_search` / `code_search` tools **cannot find** strings inside Python f-string template literals in `voxel_editor_html.py`. The file uses `{{` and `}}` for literal braces and `{variable}` for interpolation, which breaks literal string matching.

**Example**: Searching for `ySliceMax` or `rebuildMesh` in the `.py` file returns **no results** even though these strings exist in the template.

**Solution**: When searching for JS/HTML content inside `voxel_editor_html.py`:
1. **Do NOT use `grep_search`** — it will fail silently
2. **Use `read_file`** with offset/limit to scan sections directly
3. Key line ranges in `voxel_editor_html.py` (as of Aug 8, 2026):
   - **HTML panel (right panel)**: ~line 275-315 (slice sliders, shortcuts, tool colors)
   - **JS variables (yMin, xMin, zMin, etc.)**: ~line 670-680
   - **`getVisibleVoxels()` function**: ~line 722-733 (slice filtering logic)
   - **`rebuildMesh()` function**: ~line 739-790 (instanced mesh rebuild)
   - **Slice slider event handlers**: ~line 1600-1690 (Y/X/Z slider wiring + `updateLayerInfo()`)
   - **`setTool()` function**: ~line 1543-1577 (tool switching, escape reset)
   - **`updateHighlight()` function**: ~line 1264-1530 (raycasting, tool previews)
4. Alternatively, search the **generated** `voxel_editor.html` file (but it may be overwritten by scripts)

## 2. Fire Escape Design Workflow

### Historical Context (1920s NYC Tenement Fire Escapes)

- **1860 NYC Ordinance**: Required fire escapes on buildings with 8+ families
- **1901 Tenement House Act**: Mandated fixed staircases (not just vertical ladders)
- **Structure**: Balconies (landings) at each floor → zigzag stairs between → drop ladder at bottom → roof ladder at top
- **Drop ladder**: Sliding ladder in iron guide tracks from lowest landing to street
- **Roof ladder**: Vertical ladder from top landing to roof scuttle (required by law)
- **Max protrusion**: 4 feet from wall face (NYC building code)
- **Material**: Wrought iron (post-1900) or cast iron (pre-1900)

### Design Process

#### Step 1: Hand-Design in Voxel Editor

User designs the fire escape as a standalone model in the browser editor:
- Materials: `DARK_IRON` (109) for structure, `PAINTED_METAL` (111) for railings
- Landings at 8-voxel spacing (matches `story_h=8` in tenement)
- Stairs zigzag between landings
- Export as JSON (`Fireescape_test.json`)

#### Step 2: Alignment Correction

The hand-designed model may not have perfect 8-voxel spacing. Fix with piecewise Y-shift:

```python
# Original landings: Y=14, 23, 31, 40 (gaps: 9, 8, 9)
# Target landings:  Y=12, 20, 28, 36 (gaps: 8, 8, 8)
# Shift rule:
#   Y < 21:  shift 0   (landing 1 + stairs)
#   Y 21-37: shift -1  (landing 2 + stairs)
#   Y >= 38: shift -2  (landing 3 + stairs + roof)
```

Script: `shift_fe.py` — shifts all voxels down by 2, then `fix_fe_spacing.py` applies the piecewise correction.

#### Step 3: Buffer Expansion

The tenement's original 4-voxel buffer is too small for a 7-voxel-deep fire escape. Solution:
- Regenerate tenement core at `w=80, d=80` (was 88×88)
- Pad with 8-voxel buffer (was 4) → total still 96×96
- This gives 8 voxels of decoration space on all four sides

**Critical**: The total footprint MUST remain 96×96 to fit the game map. The game uses `BuildingVoxelWidth=32` with `buildingsPerBlockRow=3` → 96 voxels per block.

#### Step 4: Bolt-On

Script: `fix_fe_spacing.py` performs the full bolt-on:

1. **Regenerate** tenement at 80×80 core with 8-voxel buffer → 96×96
2. **Remove** old fire escape voxels (DARK_IRON) from all buffer zones
3. **Place** fire escape in back buffer: wall at z=87, FE spans z=87..93
4. **Add drop ladder**: vertical rungs from Y=1 to Y=12 with guide rails
5. **Add roof ladder**: vertical rungs from Y=37 to Y=42 (per 1860 ordinance)
6. **Add support posts**: 4 vertical iron posts from ground to first landing

### Alignment Reference

| Landing | Y | Tenement Window | Window Range | Coverage |
|---------|---|----------------|-------------|----------|
| 1st | 10 | Floor 0 | Y=12-16 | 2v below sill ✓ |
| 2nd | 18 | Floor 1 | Y=20-24 | 2v below sill ✓ |
| 3rd | 26 | Floor 2 | Y=28-32 | 2v below sill ✓ |
| 4th | 34 | Floor 3 | Y=34-38 | 2v below sill ✓ |

### Tenement Window Formula

```python
# From procedural_mob_buildings.py generate_apartment_block():
ground_h = 10
story_h = 8
n_floors = 5
# Windows on upper floors (floor 0 to n_floors-2):
y_base = ground_h + floor * story_h + 2  # e.g., 12, 20, 28, 36
y_top = y_base + 4                        # e.g., 16, 24, 32, 40
```

### Landing Extension (2-Window Coverage)

Historical fire escapes typically cover **2 windows per landing**. The original hand-designed landings covered only 1 window (width=19, X=67-85). Extension process:

1. **Analyze** window positions on the back wall (material 112 = glass)
   - 6 windows per floor, 3v wide, 8v spacing: X=18-20, 29-31, 40-42, 51-53, 62-64, 73-75
2. **Copy** the leftmost 8 columns of each landing platform (X=67-74) and paste shifted -8 in X (to X=59-66)
3. **Extend railings** — copy vertical railing posts above each landing platform
4. **Add support posts** — vertical iron posts from ground to each landing at the new leftmost X

Result: Landings extend from X=59-85 (width=27), covering windows 4 (X=62-64) and 5 (X=73-75).

Script: `extend_landings.py`

**⚠️ Gotcha**: Landing Y levels for FE platforms are at Y=10,18,26,34 (the actual platform surface), NOT Y=9,17,25,33 which are cornice/floor slab levels with 600+ building-wide voxels. Always verify by checking X extent — real FE landings have X=67-85, cornice levels span the entire building X=8-87.

### Mirroring (Left ↔ Right)

To move the fire escape from back-left to back-right (matching original `tenement_block_0`):

```python
# Mirror FE voxels across X axis
new_x = W - 1 - old_x  # W=96, so new_x = 95 - old_x
# Only mirror FE materials (DARK_IRON=109, PAINTED_METAL=111)
# Building voxels stay in place
```

Result: FE moves from X=59-85 (left) to X=10-36 (right). Z and Y unchanged.

Script: `mirror_fe.py`

### Duplication & 90° Rotation (Multi-Wall Fire Escapes)

To add a second fire escape on a different wall, rotate the FE 90° and place on the adjacent wall:

```python
# Rotation mapping (90° CCW around Y):
# Back wall FE:  width=X(10-36), protrusion=Z(87-93)
# Left wall FE:  protrusion=X(88-94), width=Z(10-36)
#
# new_x = old_z + 1   (87→88 wall face, 93→94 outermost)
# new_z = old_x         (10→10 near front, 36→36 further back)
# new_y = old_y         (unchanged)
```

Key rules:
- **Don't overwrite** existing building voxels — only place FE where `grid[nx,ny,nz] == 0`
- **Same landing Y levels** — both fire escapes share Y=10,18,26,34
- **Buffer check** — protrusion must stay within 8-voxel buffer (X=88-94 or Z=88-94)
- Some voxels will be clipped where the rotated FE overlaps the building corner — this is expected

Script: `add_side_fe.py`

### Roof Buffer

The original tenement height (H=44) leaves no room above the roof slab (Y=42-43) for decorations.

**Solution**: Add `roof_buf=8` parameter to `generate_apartment_block()`:
- Grid height becomes `h + roof_buf` = 52 (or 60 with user edits)
- Building floors stay at Y=10,18,26,34,42 (unchanged)
- Y=44-51 available for water tower, chimneys, parapet, roof access shed
- No game-side height constraint exists — chunk system adapts to `.stasset` dimensions

## 3. Game Map Constraints

### Block Sizing (from `CityMap3D.cs`)

```csharp
private const int BuildingVoxelWidth = 32;
// GroundTileSize = (32 * 3 * 0.1) + 1.0 * 2 = 11.6 world units
// Spacing = 11.6 + 1.6 (road) = 13.2 world units
```

- Each block = 3×3 building slots
- Each building = 32×32 voxels at `voxelSize=0.1` → 3.2 world units
- Full block building (tenement) = 96×96 voxels → 9.6 world units
- **Buildings MUST be 96×96 in X/Z** — any larger overflows into sidewalk/road

### Tenement Structure

| Property | Value |
|----------|-------|
| Core (original) | 88×88 voxels |
| Core (new, with 8v buffer) | 80×80 voxels |
| Buffer (original) | 4 voxels each side |
| Buffer (new) | 8 voxels each side |
| Total footprint | 96×96 voxels (unchanged) |
| Height (original) | 44 voxels |
| Height (with roof_buf=8) | 52 voxels |
| Roof buffer | 8 voxels (Y=44-51 for decorations) |
| Floors | 5 (ground_h=10, story_h=8) |
| Wall thickness | 2 voxels (WALL_T) |
| Floor slab thickness | 1 voxel (FLOOR_T) |
